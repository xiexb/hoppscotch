# ERD 版本管理与版本对比功能 — 实施计划（v3 - Git 每集合独立仓库）

## 1. 目标

为 Hoppscotch 的每个集合（Collection）提供基于 Git 的版本管理能力：
- **自动版本控制**：每次保存自动生成 git commit
- **版本对比**：选择任意两个版本，颜色高亮差异（绿色=新增、黄色=变更、灰色=删除）
- **每集合独立仓库**：每个 Team Collection 拥有独立的 git 仓库
- **远程推送**：自动 push 到 GitHub/GitLab 远程仓库
- **可扩展**：仓库结构预留 API 定义和测试用例的版本管理空间
- **认证保护**：所有版本管理 API 需要 JWT 认证

### 2.3 远程推送策略

提供两种远程仓库模式，用户首次配置时选择：

**模式 A: 单仓库多分支（推荐）**
```
远程: git@github.com:<org>/hoppscotch-versions.git
分支: erd/<team-id>/<collection-id>
优点: 仓库数量少，管理简单
```

**模式 B: 每集合独立仓库**
```
远程: git@github.com:<org>/erd-<collection-name>.git
分支: main
优点: 权限隔离更清晰，但仓库多
```

后端在 `.env` 中配置默认远程 URL 模板：
```env
ERD_VERSION_REMOTE_URL=git@github.com:xiexb/hoppscotch-versions.git
ERD_VERSION_REMOTE_MODE=branch    # "branch" 或 "repo"
ERD_VERSION_SSH_KEY=/data/keys/deploy_key  # SSH 私钥路径
```

### 2.4 自动 Commit 策略

每次用户点击"保存"或自动保存触发时：

1. 后端对比当前 ERD JSON 与上次 commit 的 normalized.json
2. 如果有变更：
   - 写入新文件
   - 生成描述性 commit message（自动分析变更内容）
   - git add + commit
   - 异步 git push（不阻塞响应）
3. 如果无变更：跳过，不生成空 commit

**Commit Message 格式**：
```
erd: add 2 tables, modify users.email type, remove legacy_orders

Tables: +user_roles, +permissions
Modified: users (email: VARCHAR→TEXT, +phone column)
Removed: legacy_orders
```

如果变更太大（超过阈值），简化为：
```
erd: auto-save 2026-06-01 15:30 (3 tables, 12 columns changed)
```

## 3. 后端 API 设计

### 3.1 认证模式

所有接口使用 `@UseGuards(JwtAuthGuard)` + `@GqlUser() user: AuthUser`。
与现有 `access-token.controller.ts` 模式一致。

### 3.2 API 接口

```
基础路径: /api/v1/erd-version

所有接口需要:
  Header: Authorization: Bearer <JWT_TOKEN>
  Query:  teamId (团队ID)
          collectionId (集合ID)

─────────────────────────────────────

POST /commit
  Body: { erdJson: string, message?: string }
  行为: 
    1. 获取或初始化该集合的 git 仓库
    2. 写入 erd-schema.json + erd-schema.normalized.json
    3. 自动生成 commit message（如果未提供）
    4. git add + commit
    5. 异步 git push
  Response: { 
    commitHash: string, 
    message: string, 
    timestamp: string,
    stats: { tablesAdded, tablesRemoved, columnsAdded, columnsRemoved, ... }
  }

GET /log?limit=20&offset=0
  行为: git log --oneline --stat
  Response: [{
    hash: string,
    shortHash: string,
    message: string,
    author: string,
    date: string,
    stats: { files, insertions, deletions },
    tags: string[]
  }]

GET /:ref
  行为: git show <ref>:erd/erd-schema.json
  Response: { erdJson: string, commit: { hash, message, date } }

GET /diff?from=<ref1>&to=<ref2>
  行为: 读取两个版本的 normalized.json，运行结构化 diff
  Response: DiffResult

POST /restore/:ref
  行为: git show <ref>:erd/erd-schema.json → 返回给前端
  Response: { erdJson: string }

GET /stats/:ref
  行为: 统计某版本的表/列/关系数量
  Response: { tables: number, columns: number, relationships: number }

PUT /remote
  Body: { 
    remoteUrl: string,           # git@github.com:org/repo.git
    mode: "branch" | "repo",    # 推送模式
    sshKeyPath?: string          # 可选自定义 SSH key
  }
  行为: 配置该集合仓库的远程地址
  Response: { success: true, remoteUrl: string }

GET /remote
  行为: 获取当前远程配置
  Response: { remoteUrl: string, mode: string, lastPushAt: string }

POST /push
  行为: 手动触发 git push
  Response: { success: true, pushed: number }

DELETE /commit/:ref
  行为: git revert (逻辑删除，不丢历史)
  Response: { success: true, revertHash: string }

GET /export
  行为: git archive HEAD → 返回 .tar.gz
  Response: Binary stream (Content-Disposition: attachment)
```

### 3.3 normalized.json 格式

```json
{
  "version": "3.0.0",
  "generatedAt": "2026-06-01T14:30:00Z",
  "tables": [
    {
      "name": "users",
      "comment": "用户表",
      "columns": [
        {
          "name": "id",
          "type": "BIGINT",
          "pk": true,
          "notNull": true,
          "autoIncrement": true,
          "default": "",
          "comment": "主键ID"
        }
      ]
    }
  ],
  "relationships": [
    {
      "type": "one-to-many",
      "from": "users.id",
      "to": "orders.user_id"
    }
  ]
}
```

- 去除 UUID、坐标、宽度等 UI 噪音
- 按表名、列名字母排序
- `git diff` 直接可读

## 4. Diff 算法

### 4.1 对比匹配策略

```
1. 按 table.name 匹配两个版本的表
2. 对匹配的表，按 column.name 匹配列
3. 对比每个列的: type, default, comment, pk, notNull, unique, autoIncrement
4. 对比表级别的: comment
5. 对比 relationships: 按 (fromTable.fromCol → toTable.toCol) 四元组匹配
```

### 4.2 DiffResult 结构

```typescript
interface DiffResult {
  tables: {
    added: { name: string; comment: string; columnCount: number }[]
    removed: { name: string; comment: string; columnCount: number }[]
    modified: TableModified[]
  }
  relationships: {
    added: RelInfo[]
    removed: RelInfo[]
  }
  summary: {
    tablesAdded: number; tablesRemoved: number; tablesModified: number
    columnsAdded: number; columnsRemoved: number; columnsModified: number
    totalChanges: number
  }
}

interface TableModified {
  tableName: string
  changes: {
    comment?: { old: string; new: string }
    columns: {
      added: ColumnInfo[]
      removed: ColumnInfo[]
      modified: ColumnModified[]
    }
  }
}

interface ColumnModified {
  columnName: string
  changes: { property: string; old: any; new: any; label: string }[]
}
```

### 4.3 视觉差异展示

前端收到 DiffResult 后，合并两个版本的 erd-editor JSON 为"diff 视图"：

| 状态 | 颜色 | erd-editor ui.color |
|------|------|---------------------|
| 新增表/列 | 绿色 | `#22c55e` |
| 变更表/列 | 黄色 | `#eab308` |
| 删除表/列 | 灰色 | `#6b7280` (从旧版本提取回来显示) |
| 未变化 | 原色 | `""` (空字符串) |

## 7. 技术风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| git push 失败 (网络/权限) | 版本只在本地 | push 失败不阻塞 commit，记录失败日志，面板提示"未推送" |
| 并发保存导致 git 冲突 | commit 失败 | 后端 mutex 锁，同一集合串行 git 操作 |
| SSH key 过期/变更 | push 失败 | 配置健康检查，失败时提醒用户更新 |
| simple-git 阻塞事件循环 | API 响应慢 | async/await + 超时控制，push 操作放 worker thread |
| UUID 变化导致 diff 不准 | 对比结果有误 | normalized.json 按名称匹配，不依赖 UUID |
| 大量集合 = 大量仓库 | 磁盘/管理压力 | 定期清理空仓库，提供仓库统计 API |
| ERD 页面无集合概念 | 不知道存哪个仓库 | 需要扩展 ERD 页面，关联当前集合 |

