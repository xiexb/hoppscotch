#### 1.4.2 TestCaseRunnerService (新建 Dioc Service)

```typescript
// services/test-case-runner.service.ts
class TestCaseRunnerService extends Service {
  // 依赖
  private interceptorService = use(KernelInterceptorService)
  private envStore = use(EnvironmentsService)

  async runTestCase(
    request: HoppRESTRequest,
    testCase: HoppRESTTestCase,
    inheritedProperties: HoppInheritedProperty
  ): Promise<TestCaseResult> {
    // 1. 合并 requestOverrides 到 request
    const mergedRequest = this.applyOverrides(request, testCase.requestOverrides)

    // 2. 获取 effective request
    const effective = getEffectiveRESTRequest(mergedRequest, environment)

    // 3. 执行网络请求
    const response = await createRESTNetworkRequestStream(effective)

    // 4. 比对 expectations vs actual
    return this.compareExpectations(testCase.expectations, response)
  }

  private compareExpectations(
    expectations: HoppRESTTestCaseExpectations,
    response: HoppRESTSuccessResponse
  ): TestCaseResult {
    const details: AssertionDetail[] = []

    // statusCode 比对
    if (expectations.statusCode !== null) {
      details.push({
        type: "statusCode",
        expected: String(expectations.statusCode),
        actual: String(response.statusCode),
        pass: response.statusCode === expectations.statusCode
      })
    }

    // bodyContains 比对
    const bodyText = new TextDecoder().decode(response.body)
    for (const text of expectations.bodyContains) {
      details.push({
        type: "bodyContains",
        expected: text,
        actual: bodyText.substring(0, 100) + "...",
        pass: bodyText.includes(text)
      })
    }

    // headerExists 比对
    for (const headerName of expectations.headerExists) {
      const found = response.headers.some(
        h => h.key.toLowerCase() === headerName.toLowerCase()
      )
      details.push({
        type: "headerExists",
        expected: headerName,
        actual: found ? "存在" : "不存在",
        pass: found
      })
    }

    // jsonPath 比对 (需要 jsonpath-plus 库)
    for (const jp of expectations.jsonPath) {
      try {
        const json = JSON.parse(bodyText)
        const result = JSONPath({ path: jp.path, json })
        const actualValue = result?.[0]
        const pass = this.compareWithOperator(actualValue, jp.value, jp.operator)
        details.push({ type: "jsonPath", expected: `${jp.path} ${jp.operator} ${jp.value}`, actual: String(actualValue), pass })
      } catch (e) {
        details.push({ type: "jsonPath", expected: jp.path, actual: "parse error", pass: false })
      }
    }

    return {
      status: details.every(d => d.pass) ? "pass" : "fail",
      details,
      responseTime: response.meta?.responseTime ?? 0,
      response // 保存完整响应用于后续查看
    }
  }
}
```

### 2.2 Apifox 前置URL模型

```
Apifox URL 解析架构:
  Environment
    ├── variables: { "token": "xxx", ... }
    └── baseUrls: { "serverId1": "https://prod.api.com", "serverId2": "..." }

  projectSetting.servers
    └── [{ id: "serverId1", name: "NB锁服务", moduleId: 6107393 }, ...]

  Folder/API
    └── serverId: "serverId1"  (空字符串 = 继承父级)

  运行时 URL = environment.baseUrls[resolvedServerId] + api.path
```

**关键设计**:
- Servers 是命名的 base URL，作用域为模块(顶级文件夹)
- 每个环境存储 serverId→URL 的映射
- 文件夹和 API 通过 serverId 引用，空值=继承
- 切换环境 = 切换所有服务的 URL

## 已识别的风险和坑点

### 6.1 测试用例模式

| # | 风险 | 严重度 | 说明 |
|---|------|--------|------|
| R1 | RequestTestCasesPanel 无 DI 访问权限 | 高 | 组件是纯 Vue props，无 useService()。需要提升到父组件注入或重构为 Dioc-aware |
| R2 | JSONPath 表达式安全 | 中 | jsonpath-plus 在浏览器中执行用户输入的表达式，需防范原型污染 |
| R3 | 测试用例执行顺序 | 中 | "Run All" 需要串行执行并收集结果，不能并行 (环境变量可能被脚本修改) |
| R4 | 响应体 ArrayBuffer 解码 | 低 | response.body 是 ArrayBuffer，需要 TextDecoder + JSON.parse，大文件可能 OOM |
| R5 | 参数覆盖与 pre-request script 冲突 | 中 | 如果 test case 覆盖了 body，pre-request script 是否还能修改？需要明确优先级 |

### 6.2 前置URL与环境变量分离

| # | 风险 | 严重度 | 说明 |
|---|------|--------|------|
| R6 | endpoint 字段兼容性 | **高** | 现有数据 endpoint 存储完整 URL。改为相对路径需要迁移脚本或在解析时兼容 |
| R7 | pre-request script 修改 endpoint | 高 | 脚本可以修改 request.endpoint，如果改为 path-only 语义，脚本行为改变 |
| R8 | Team Environment 后端变更 | 中 | 后端 GraphQL schema 需要添加 servers 字段到 TeamEnvironment，涉及 Prisma migration |
| R9 | Codegen.vue 使用 endpoint | 中 | 代码生成器读取完整 URL，需要适配 baseUrl + path 模式 |
| R10 | 环境变量 `<<baseUrl>>` 习惯 | 低 | 很多用户已习惯用 `<<baseUrl>>/path` 模式，需保持向后兼容 |
| R11 | Apifox 导入 servers 映射 | 中 | 导入器需要从 Apifox 的 baseUrls map 转换为 servers array |
| R12 | inheritedBaseUrl 字段冲突 | 中 | v20 已有 inheritedBaseUrl 字段但未使用，新功能可能与之冲突 |

### 6.3 请求Body模型配置

| # | 风险 | 严重度 | 说明 |
|---|------|--------|------|
| R13 | HoppRESTReqBody 是 zod union | 中 | body.body 形态随 contentType 变化 (null/Array/File/string)，schema tree 需适配 |
| R14 | 表格编辑与 schema tree 同步 | **高** | 用户在表格中修改参数后，schema tree 应如何更新？两个数据源可能不一致 |
| R15 | WorkspaceModelService 仅 IndexedDB | 低 | 模型存储在本地 IndexedDB，团队协作时模型不共享 (已有此限制) |
| R16 | PreviewView 死代码激活 | 低 | (request as any).bodySchemaTree 需要改为正式字段路径 |
| R17 | SchemaTreeEditor 的 provide/inject | 中 | 组件使用 provide/inject 传递 model resolver，嵌入新父组件时需要确保 provide chain 正确 |
