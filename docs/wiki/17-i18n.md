# Internationalization (i18n)
Hoppscotch's internationalization (i18n) system provides multi-language support across the entire application, enabling users to interact with the UI in their preferred language. The system is built on **vue-i18n** with lazy-loaded locale files and a language selector component.

## Overview
The i18n system in Hoppscotch is designed to support a growing number of languages (currently over 30) with a flexible architecture that allows:

- **Lazy-loaded locale files**: Translation files are loaded on demand when a user switches languages, reducing initial bundle size.
- **Fallback language support**: If a translation key is missing in the selected language, it gracefully falls back to English (`en`).
- **Language persistence**: The user's language preference is stored in `localStorage` via the `PersistenceService`, so it persists across sessions.
- **Automatic locale detection**: On first visit, the system attempts to detect the user's language from their browser's `navigator.language` setting.
- **RTL text direction support**: Languages like Arabic (`ar`) can specify a right-to-left (`rtl`) text direction.
- **Pluggable message extensions**: Other packages (e.g., `hoppscotch-sh-admin`) can extend the common package's translations via `registerAdditionalMessages()`.
- **Legacy URL migration**: Old URL-based locale paths (e.g., `/es/settings`) are automatically detected and migrated to the new storage-based approach.

The system replaces the previous Nuxt-based i18n approach. Instead of embedding locale codes in URLs, the current system stores the language preference in the application's local config store (`localStorage`).

## Architecture
The i18n system follows a **module-based architecture** integrated into Hoppscotch's `HoppModule` lifecycle. The core module initializes `vue-i18n` during the Vue app initialization phase, resolves the user's preferred locale, and sets up the translation infrastructure.

### Supported Languages
Hoppscotch currently supports **32 languages** including English (`en`), Chinese Simplified (`cn`), Chinese Traditional (`tw`), Spanish (`es`), French (`fr`), German (`de`), Japanese (`ja`), Korean (`ko`), Arabic (`ar`, RTL), Russian (`ru`), and many more.

## Translation Files Structure
Translation files are JSON files located in the `locales/` directory. Each file is a flat/dictionary of nested translation keys organized by feature domain.

>
Source: [locales/en.json](https://github.com/xiexb/hoppscotch/blob/main/packages/hoppscotch-common/locales/en.json#L1-L81)

json1{
2  "action": {
3    "add": "Add",
4    "cancel": "Cancel",
5    "clear": "Clear",
6    "copy": "Copy",
7    "delete": "Delete",
8    "save": "Save",
9    "search": "Search",
10    "send": "Send"
11  },
12  "settings": {
13    "general": "General",
14    "general_description": "Configure general application settings"
15  },
16  "error": {
17    "something_went_wrong": "Something went wrong"
18  }
19}
Keys are accessed using dot notation, e.g., `t("action.save")` or `t("error.something_went_wrong")`.

>

#### `FALLBACK_LANG: LanguagesDef`
The fallback language object (defaults to English).

>
Source: [modules/i18n.ts](https://github.com/xiexb/hoppscotch/blob/main/packages/hoppscotch-common/src/modules/i18n.ts#L58-L64)

#### `changeAppLanguage(locale: string): Promise<void>`
Changes the application language to the specified locale.

**Parameters:**

- `locale` (string): The locale code to switch to (e.g., `"fr"`, `"ja"`)

**Behavior:**

- Dynamically imports the locale JSON file from `locales/{locale}.json`
- Throws an error if the locale file doesn't exist
- Merges any additional registered messages for this locale
- Updates the `vue-i18n` locale ref
- Persists the selection to `localStorage` via `PersistenceService`

**Throws:**

- `Error("Tried to change app language to non-existent locale '{locale}'")` if the locale file is not found
- `Error("Tried to change language without active i18n instance")` if `i18n` is not initialized

>
Source: [modules/i18n.ts](https://github.com/xiexb/hoppscotch/blob/main/packages/hoppscotch-common/src/modules/i18n.ts#L158-L184)

#### `registerAdditionalMessages(locale: string, messages: Record<string, unknown>): void`
Registers additional translation messages for a specific locale. Allows other packages to extend the common package's translations.

**Parameters:**

- `locale` (string): The locale code to extend (e.g., `"en"`, `"fr"`)
- `messages` (Record<string, unknown>): The additional messages to merge

**Behavior:**

- If the i18n instance is already initialized and the locale is loaded, messages are merged immediately
- Otherwise, messages are queued and merged when the locale is loaded

>
Source: [modules/i18n.ts](https://github.com/xiexb/hoppscotch/blob/main/packages/hoppscotch-common/src/modules/i18n.ts#L85-L99)

#### `getI18n(): I18n["global"]["t"]`
Returns the `vue-i18n` global `t()` translation function.

**Returns:** The `t()` function from the `vue-i18n` global instance.

>
Source: [modules/i18n.ts](https://github.com/xiexb/hoppscotch/blob/main/packages/hoppscotch-common/src/modules/i18n.ts#L189-L191)

## Configuration Options
The i18n system does not have user-configurable settings beyond the language selection. However, the default `vue-i18n` configuration is set as follows:

OptionValueDescription`locale``"en"`Default locale (overridden by `resolveCurrentLocale()` on init)`fallbackLocale``"en"`Fallback locale when a translation key is missing`legacy``false`Use Composition API mode (not legacy mode)`allowComposition``true`Allow using composition API with vue-i18n
