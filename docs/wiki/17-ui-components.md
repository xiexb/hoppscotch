# UI Component Library
Hoppscotch provides a reusable UI component library built on Vue 3, Tailwind CSS, and the `@hoppscotch/ui` (v0.2.5) npm package. This library exports a set of design system components, a Tailwind CSS preset, and a `Toaster` utility for building consistent user interfaces across the Hoppscotch ecosystem.

## Overview
The UI Component Library is the foundational design system for Hoppscotch, offering a consistent set of reusable Vue components that span buttons, modals, inputs, tabs, navigation items, and more. The library is designed to:

- **Maintain visual consistency** across all Hoppscotch packages (common app, self-hosted web, desktop, admin panel, and agent)
- **Reduce boilerplate** by encapsulating common UI patterns like confirmation dialogs, slide-over panels, and tabbed interfaces
- **Support theming** via a shared Tailwind CSS preset that defines color schemes, spacing, and typography tokens
- **Provide accessibility** out of the box with proper ARIA attributes and keyboard navigation support

All UI components are imported from the `@hoppscotch/ui` npm package, which is automatically registered globally via the `unplugin-vue-components` plugin — meaning components can be used directly in Vue templates without manual imports.

The library stitches together:

- **Button components** (`HoppButtonPrimary`, `HoppButtonSecondary`) for primary and secondary actions
- **Smart input and form controls** (`HoppSmartInput`, `HoppSmartCheckbox`, `HoppSmartRadio`, `HoppSmartRadioGroup`, `HoppSmartToggle`, `HoppSmartSelectWrapper`)
- **Modal and overlay components** (`HoppSmartModal`, `HoppSmartConfirmModal`, `HoppSmartSlideOver`)
- **Navigation and container components** (`HoppSmartTabs`, `HoppSmartTab`, `HoppSmartWindows`, `HoppSmartWindow`, `HoppSmartItem`)
- **Feedback and state components** (`HoppSmartSpinner`, `HoppSmartPlaceholder`, `HoppSmartProgressRing`, `HoppSmartIntersection`)
- **Link and media components** (`HoppSmartAnchor`, `HoppSmartLink`, `HoppSmartPicture`, `HoppSmartFileChip`)
- **Utility** (`HoppSmartTree`, `Toaster` notification system)

The most common pattern is a modal dialog containing form inputs with action buttons. This example shows the "Add Folder" component using `HoppSmartModal`, `HoppSmartInput`, `HoppButtonPrimary`, and `HoppButtonSecondary`:

4    dialog
5    :title="t('folder.new')"
6    @close="emit('hide-modal')"

8    <template #body>
9      <HoppSmartInput
10        v-model="editingName"
11        placeholder=" "
12        input-styles="floating-input"
13        :label="t('action.label')"
14        @submit="addFolder"
15      />
16    </template>
17    <template #footer>
18      <span class="flex space-x-2">
19        <HoppButtonPrimary
20          :label="t('action.save')"
21          :loading="loadingState"
22          outline
23          @click="addFolder"
24        />
25        <HoppButtonSecondary
26          :label="t('action.cancel')"

28          filled
29          @click="hideModal"

32    </template>

34</template>

## Design Intent
The UI Component Library follows several intentional design principles:

-
**Global auto-imports**: By using `unplugin-vue-components`, the team avoids repetitive import statements. Components are declared globally, which keeps templates clean and reduces boilerplate. This was a deliberate choice to improve developer experience in a large-scale Vue application.

-
**Separation of design tokens from component logic**: The Tailwind CSS preset (`@hoppscotch/ui/ui-preset`) separates visual tokens from Vue component implementation. This allows the design system to evolve independently — color palettes and spacing can be updated without touching component code.

-
**Consistency across packages**: By publishing UI components as a standalone npm package (`@hoppscotch/ui`), every package in the monorepo (common, desktop, admin, self-hosted, agent) shares exactly the same UI primitives. This prevents UI drift between different build targets.

-
**Composition over configuration**: Components like `HoppSmartModal` expose slots (`#body`, `#footer`) rather than complex prop configurations. This follows Vue's slot-based composition model, giving feature developers full flexibility in layout while maintaining structural consistency.
